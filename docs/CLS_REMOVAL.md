# Сначала убрать очки: разбор 22c0ae9 и следующий тест

В этой проверке сохранение лица, фона и других свойств не является целью.
Вмешательства остаются отдельными для всех image tokens после всех 19 double-блоков.
Локально выполнялись только проверки на маленьких случайных CPU-моделях.
Удаление очков новым режимом ещё нужно проверить на кластере.

## Что показал 22c0ae9

Просмотрены финальные PNG, one-step оценки пары glasses_000 на sigma 1 и 0.25,
предсказания шага 0 до/после оптимизации и три проверки первого обновления.
SHA исходников в provenance совпадают с кодом, на котором добавлен этот коммит.
Во всех шести режимах PNG alpha=0 совпадает с baseline побайтово.
В именах `alpha1` — индекс в списке `[0, 0.5]`, фактическая alpha равна **0.5**.

| Режим | Финальный сдвиг вдоль чистого mean-diff | Loss на последнем шаге: до → после 20 обновлений | Очки на финальном PNG |
| --- | --- | --- | --- |
| opt_clean | 0.66392 | 0.026418 → 0.008095 | Есть |
| opt_noised_paired | 0.60155 | 0.026662 → 0.009404 | Есть |
| opt_noised_shared | 0.48609 | 0.026673 → 0.007540 | Есть |

Это не вероятности отсутствия очков. Без положения исходного CLS относительно
центроидов неизвестно, пересекли ли результаты границу классов. Сохранённые PNG
и JSON выборки не содержат самих CLS-векторов; они есть в `*_cls_targets.pt`
исходных выходных каталогов на кластере.

Сдвиг alpha=0.5 задаёт половину средней разницы классов до нормировки целевого
вектора. Если источник близок к положительному центроиду, такой сырой target
находится примерно между центроидами. Это не команда гарантированно убрать очки.
Loss после 20 обновлений остаётся заметно выше нуля: точного достижения даже
этой цели не показано. Увеличение alpha нужно проверить отдельно от LR.

В noised-paired AUC=1 на train/val/test на всех уровнях. В shared AUC=0.5
при sigma=1 и 1 на val/test на остальных уровнях. Предпросмотры визуально
согласуются с этим: paired различает очки; shared на sigma=1 даёт две одинаковые
картинки, поскольку вход содержит только общий шум и общий prompt.
На sigma=0.25 нормы направлений paired/shared равны 0.45933/0.45884, у чистого
направления — 0.45806. Близкие нормы не доказывают совпадение направлений.
Разделимость естественных картинок не гарантирует семантику градиентного редактирования.

### Численная оптимизация

Один Adam proposal при LR=0.01 проверялся с разными множителями, без применения
проб к итоговому прогону. Положительный множитель следует направлению Adam.

| Точность | Delta loss при множителе +0.001 | Delta loss при полном proposal +1 | Относительное L2-различие повторных градиентов по блокам |
| --- | --- | --- | --- |
| BF16 | +0.002786 | +0.062938 | 3.00–4.10% |
| FLUX BF16, VAE FP32 | +0.003994 | +0.060799 | 1.98–2.38% |
| FLUX/VAE FP32 | −0.001531 | +0.065545 | 5.61–7.77% |

В BF16 все проверенные ненулевые положительные множители повышают loss.
В FP32 самый маленький положительный множитель снижает loss; соответствующий
отрицательный повышает его. Это аргумент начать FP32-тест с LR=0.00001,
но не доказательство точности всей цепочки градиента: повторный backward
различается даже в FP32, а конечные разности не совпадают точно с линейным прогнозом.
Причина этих различий пока не локализована. У FP32 также другой baseline при том
же seed, поэтому сравнивать нужно эффект относительно baseline каждого режима.

В opt_noised_paired на sigma=0.75 ни одна итерация не лучше нулевой;
`selection=last` всё равно применяет последнее состояние.
RMS-потолок и штраф сохранения в этих прогонах уже отключены.

## Loss только вдоль концепта

Старый `cls_loss: "shifted_cls"` сохраняется по умолчанию:

```
target = normalize(CLS_source - alpha * direction)
loss = 0.5 * ||CLS - target||²
```

Расстояние до всего вектора штрафует и изменения поперёк направления,
даже при `preservation_weight=0`. Новый `cls_loss: "projection"` использует:

```
unit = direction / ||direction||
target_score = <CLS_source, unit> - alpha * ||direction||
loss = 0.5 * relu(sign(alpha) * (<CLS, unit> - target_score))²
```

Для положительной alpha нужно перейти в сторону отсутствия концепта минимум
на alpha средних разниц. Остальные координаты CLS свободны; после пересечения
цели loss не тянет результат назад. Отрицательная alpha поддерживает добавление
концепта. Нормировка самого DINO CLS сохраняется, целевой полный вектор в этом
режиме не нормируется. Значение цели вне геометрически достижимого диапазона
unit CLS логируется как `projection_target_reachable=false`, без скрытого clipping.

Требование относится к проекции DINO, а не к независимому детектору очков.
Если проекция достигает области отрицательного класса, но очки видны, увеличение
этой же метрики не является подтверждённым решением.

Во всех новых конфигах отсутствуют маски токенов, штрафы сохранения изображения,
лица и активаций, а также RMS-потолок. В FP32-конфигах `selection=best` возвращает
оценённое состояние с минимальным semantic loss; это не бюджет изменения картинки
и не откат промежуточных Adam-обновлений. Цель по-прежнему вычисляется заново на
каждом шаге. Условия и раскладка поправок одинаковы в двух FP32-конфигах.

## Разобрать уже сделанные прогоны без GPU

После получения этого кода укажите полный каталог исходного прогона, содержащий
`*_cls_targets.pt`, и точный использованный direction. Не используйте выборку
`figures/cls_noised_mean/`, в которой PT-файлов нет.

```bash
python -m src.dino_adapter.cls_experiment audit-run \
  --results /path/to/original/opt_clean \
  --direction out/cls_features/cls_direction.pt \
  --output out/opt_clean_class_scores.json
```

Для paired/shared повторите с соответствующим каталогом и его direction.
Команда проверяет SHA направления и не загружает модели.

В `steps` смотрите `source_class_score`, `target_class_score`, `selected_class_score`:

- Средний train CLS без очков имеет score 0, с очками — 1; 0.5 — середина центроидов.
- Если target остаётся со стороны положительного центроида, цель может быть слишком слабой.
- Если target около 0 или ниже, а selected заметно выше target, цель ещё не достигнута.
- Если selected около 0 или ниже, а очки остались, метрика дала нежелательный способ улучшения.

Это координата относительно train-центроидов, не вероятность и не проверенный
порог классификатора. Для noised-направлений используется центроид нужной sigma.
Аудит старых запусков показывает оценённый float CLS, не пересчитывает DINO по PNG.

## Новый запуск на кластере

Из корня SHIFT, в подготовленном GPU-окружении, начните с одного test-примера.
Пути direction замените, если у вас другой каталог чистых CLS.
Новые выходные каталоги должны отсутствовать.

```bash
git pull --ff-only origin feat/dino-invertible-adapter

python -m src.dino_adapter.cls_experiment \
  --config configs/cls_remove_projection_fp32.json \
  optimize --dataset out/dataset200 --split test --num-samples 1 \
  --direction out/cls_features/cls_direction.pt \
  --alphas 0 2 --iterations 40 \
  --output out/cls_remove_projection_fp32_first
```

Это все 19 блоков, все 4 шага, 40 Adam-обновлений на шаг, LR=1e-5, FP32 для
FLUX/VAE/DINO. На один ненулевой alpha выполняются 160 обновлений активаций;
веса моделей заморожены. FP32 требует больше памяти, чем BF16.

Для сравнения двух loss при остальных одинаковых параметрах:

```bash
python -m src.dino_adapter.cls_experiment \
  --config configs/cls_remove_shifted_fp32.json \
  optimize --dataset out/dataset200 --split test --num-samples 1 \
  --direction out/cls_features/cls_direction.pt \
  --alphas 0 2 --iterations 40 \
  --output out/cls_remove_shifted_fp32_first
```

Без переопределений конфиги используют alpha `[0, 0.5, 1, 2]` и 100 обновлений
на шаг. Переопределения `--alphas`, `--iterations`, `--learning-rate` сохраняются
в `config.json` конкретного запуска. Начальный LR выбран по одной успешной пробе,
дальнейшую сходимость нужно смотреть в логах.

Чтобы отдельно проверить только недостаточную alpha на прежней BF16-схеме,
используйте `configs/cls_remove_alpha_sweep.json`. Он сохраняет старые LR=0.01,
20 обновлений и selection=last. Это контроль гипотезы о силе target, а не
рекомендованная численно устойчивая оптимизация. С ним можно использовать уже
посчитанные BF16 noised-направления; FP32-конфиги требуют своих noised-направлений,
поэтому для первых FP32-тестов выше используется готовый **чистый** mean-diff.

Все три конфига дополнительно сохраняют `*_target_prompt_only.png`: генерацию
по prompt парной картинки без очков, без guidance. Сам guidance продолжает
использовать исходный prompt с очками; контроль не подменяет его результат.

В новых JSON есть `cls_class_scores` по шагам, `final_cls_class_score` по финальному
PNG и пометка пространства его вычисления. В итерациях логируются `projected_removal`,
`requested_projected_removal`, `remaining_mean_diffs`, `projection_target_reached`.
Сопоставляйте их с PNG и независимой оценкой очков; улучшение одного CLS-score
не считается успешным удалением. Фон и личность в этом эксперименте не оцениваются
как критерий успеха.

## Исправление screening

CLS extract, extract-noised и выбор test-prompts теперь используют общий загрузчик
`excluded_pairs.json`, как и обучение адаптера. Ранее CLS-пути обходили исключения.
Если на кластере этот файл использовался, старые CLS-артефакты нужно пересчитать
из отфильтрованных записей. Если файла не было, это исправление не меняет состав данных.
