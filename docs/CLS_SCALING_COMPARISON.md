# Сравнение RMS и прямой оптимизации поправок

Эксперимент проверяет, влияет ли масштабирование поправок на разрушение лица.
Все три конфигурации используют отдельные поправки для каждого image-токена
после всех double-блоков. На каждом из четырёх шагов диффузии выполняются
20 обновлений Adam; поправки и optimizer state создаются заново на следующем шаге.
Цель CLS пересчитывается на каждом шаге и фиксируется внутри его 20 обновлений.

Здесь используется прежний one-step loss. Локальный эксперимент с backward через
всю генерацию и общей поправкой по токенам — отдельный метод; он не входит в это
сравнение. DINO CLS, mean-diff, prompt, seed, sigma, число итераций и способ
декодирования одинаковы для всех вариантов. Новые конфиги используют alpha 0 и 0.5.

Текущие конфиги явно задают `decode_mode: "pipeline"`: RGB для DINO согласован с
выходом SHIFT. Сохранённые результаты коммита `1a0f4f2` получены до этого исправления.
Для их воспроизведения нужен `decode_mode: "legacy_fp32_unclipped"`.
Разбор и диагностика: [CLS_SCALING_AUDIT.md](CLS_SCALING_AUDIT.md).

## Три варианта

Обозначим `s = RMS(h_baseline)` по всем image-токенам и каналам одного изображения.
В каждом блоке на текущем шаге `s` фиксируется до начала оптимизации.
Для velocity вместо `h` подставляется `v`.

| Конфиг | Поправка | Adam learning rate | Adam epsilon |
| --- | --- | --- | --- |
| `configs/cls_joint_scaling_rms.json` | `h_live + s*u` | `lr` | `1e-8` |
| `configs/cls_joint_scaling_none.json` | `h_live + delta` | `lr` | `1e-8` |
| `configs/cls_joint_scaling_none_matched.json` | `h_live + delta` | `s*lr` для каждого блока | `1e-8/s` для каждого блока |

Во всех конфигурациях `max_relative_rms: null`, `preservation_weight: 0`,
`selection: "last"`. Нет проекции в бюджет, штрафа на активации или отката к лучшей
итерации. Нормировка градиента до единичной длины не применяется.

`none_matched` — контроль замены координат, а не независимый способ улучшить
редактирование. При `delta=s*u` градиенты связаны как `g_u=s*g_delta`.
Пересчёт LR **и epsilon** воспроизводит обновления Adam в исходных единицах.
В точной арифметике поправки совпадают. Округление FP32/BF16 и последующие
нелинейные блоки могут увеличивать расхождения; побитовое совпадение требуется
только для alpha=0 с baseline соответствующего запуска.

Контроль включается через `correction_scaling: "none", match_rms_adam: true`.
Он поддерживает batch size 1, потому что каждой группе Adam назначается скалярный
LR. Эксперимент и так обрабатывает лица по одному; `--num-samples 5` допустим.
Обычные `rms` и `none` не имеют этого ограничения. При отсутствии новых полей
сохраняется режим `rms` с `match_rms_adam: false`.

Ненормированный вариант `none` с общим LR меняет относительную силу вмешательства
между блоками: раньше величина обновления зависела от `s`, теперь этой зависимости
нет. Поэтому одной пары запусков с численно одинаковым LR недостаточно, чтобы
заключить, что масштабирование полезно или вредно.

## Запуск на GPU-кластере

Из корня SHIFT, в окружении с установленными зависимостями и доступом к FLUX:

```bash
bash scripts/test_cls_scaling.sh \
  out/dataset200 \
  out/cls_features/cls_direction.pt \
  out/cls_scaling_check_v2 \
  1
```

Путь к направлению укажи фактический. Скрипт использует существующие данные и
направление; сбор датасета и обучение не запускаются. Он последовательно создаёт
`rms/`, `none_matched/`, `none/` внутри нового каталога результатов, на первом
test-лице и одинаковом seed. При ошибке останавливается. Существующий каталог
результатов не перезаписывается. `out/test_cls_joint_n5` не используется.

Каждый вариант сохраняет baseline, alpha=0, alpha=0.5, one-step картинки до/после
каждого управляемого шага и JSON всех итераций. Ненулевой alpha означает
80 обновлений Adam на изображение; все выбранные блоки обновляются совместно.

После первого сравнения можно проверить общий LR прямых поправок:

```bash
python -m src.dino_adapter.cls_experiment \
  --config configs/cls_joint_scaling_none.json \
  optimize --dataset out/dataset200 --split val --num-samples 1 \
  --direction out/cls_features/cls_direction.pt \
  --learning-rate 0.001 --output out/cls_scaling_lr001_val
```

Аналогично проверь `0.01`, `0.1` с другими новыми каталогами. Это начальная сетка,
а не заранее подобранные значения. Если величины поправок не перекрываются с RMS,
расширь сетку по записанным масштабам. Для настройки LR используй val; при итоговом
сравнении выбранный LR фиксируется и проверяется на нескольких test-лицах.
CLI-переопределение сохраняется в `config.json` результата.

## Что сравнивать

1. Alpha=0 должен совпасть с baseline. Исходные baseline трёх вариантов также
   должны совпадать при одинаковом окружении и настройках детерминизма.
2. Сначала сравни `rms` и `none_matched`. Для каждого шага проверь размер поправок,
   velocity и loss. Большое раннее расхождение требует проверки реализации или
   численной устойчивости; само по себе оно ничего не говорит об удалении очков.
3. Сравни `rms` с `none` при разных LR. Контролируй величины поправок и качество
   удаления очков. Сохранение лица сравнивай при сопоставимом изменении атрибута.
4. Смотри финальные PNG: наличие очков, узнаваемость лица, артефакты в глазах,
   волосах и фоне. Падение DINO loss или CLS-проекция не подтверждают удаление очков.

В JSON для каждой выбранной sigma есть `optimizer_groups`: блок, исходный
`reference_rms`, применяемый `correction_scale`, фактические LR и epsilon Adam.
В `per_block` каждой итерации записываются `actual_relative_rms`,
`actual_absolute_rms`, `fp32_relative_rms`, `fp32_absolute_rms`.
Это RMS **накопленной поправки** на этой итерации, а не только последнего шага Adam.
`actual_*` учитывает округление к dtype FLUX. `velocity_relative_rms` показывает
изменение итогового выхода трансформера относительно baseline этой sigma.
В режимах одного блока/velocity абсолютные величины находятся в самой записи
итерации, без `per_block`.

Для явного RMS-бюджета или штрафа в других конфигах единицы остаются относительными
к исходному тензору даже при `correction_scaling: "none"`. Переключатель меняет
только параметризацию, а не определение диагностик и ограничений.

## Проверки без pretrained-моделей

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 CUDA_VISIBLE_DEVICES='' \
  OMP_NUM_THREADS=1 python -m pytest tests/test_cls_scaling.py \
  tests/test_cls_joint_guidance.py tests/test_cls_pipeline.py -q
```

Тесты сравнивают совместное вмешательство с явными обновлениями Adam, проверяют
контроль пересчёта координат при малых градиентах, сохранение смысла RMS-бюджета и
прохождение через маленький случайный SHIFT. Они проверяют реализацию; качество
редактирования настоящих лиц устанавливается по GPU-прогонам.
